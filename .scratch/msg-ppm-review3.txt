review: an int64 fill is an integer, and a batch has pixels

`fill-crosses-exactly?`'s int64 branch passed anything that was not an
exact integer, so `(full 0.5 2 #:dtype 'int64)` gave `(0 0)` while the
same predicate refused 0.5 for uint8. Both require an integer now, and
`integer?` rather than `exact-integer?` so 2.0 still crosses, the way
255.0 already does for uint8. torch truncates for both dtypes; refusing
is the departure this table already made.

`non-empty-image-batch/c` checked only that the batch had an image, so
`(zeros 2 3 0 5)` built a grid that was nothing but padding. It shares
`image/c`'s pixel check now.

The comment over `image/c` said what vision.scrbl says.
