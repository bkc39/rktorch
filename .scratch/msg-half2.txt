foreign: float16 and bfloat16 dtypes, tensor->bytes, with-autocast (#152)

The dtype enum and code table mirror the C side; dtype/c, the random
constructors' float-dtype/c and tensor's #:dtype take the half pair, with
tensor building float32 and narrowing natively since Racket has no host
vector for 16-bit floats; the repr names them as PyTorch does. A layer
moves to them, its integer buffers staying put. tensor->bytes and
bytes->tensor carry the element bytes as they are.

with-autocast, call-with-autocast, autocast-enabled? and autocast-dtype are
torch.autocast: per thread and per device type, bfloat16 unless asked for
float16, the previous state restored by dynamic-wind so the form nests and
an escape restores too. The default device names the device type.

The safetensors container now writes the payload as the element bytes with
the format's tags for all seven dtypes (F16, BF16, U8 and F64 join F32, I64
and BOOL; the existing three are byte-identical to before) and reads them
back through bytes->tensor, checking the header's shape against the
model's; copy! converts, so a file in one dtype loads into a model in
another.

Tests flip the two float16 refusals into acceptance; the half pair's
construction, readback, repr and IEEE bit patterns; the layer move; the
container with every dtype and a cross-dtype load; the autocast suite (CPU
bfloat16 matmul, nesting and escape, a Linear trained under the cast with
float32 grads, a CUDA convolution). Twins: half_dtypes.py, autocast_cpu.py
and safetensors_dtypes.py, the last a hand-built file Python's torch
writes and Racket reads, with Racket's own payload compared byte for byte.
