================================================================================
rktorch #72 -- exit-loop / "invalid memory reference" cascade
RUNBOOK for reproducing on the CUDA host (CPU and CUDA arms)
================================================================================

WHY YOU ARE RUNNING THIS
------------------------
On aarch64-darwin (Apple Silicon, Racket 9.3 CS, MPS) the cascade did NOT
reproduce in ~400 sessions, and three of issue #72's load-bearing assumptions
turned out to be false there:

  1. Exit never runs finalizers.  Registering 3000 finalizers and exiting drains
     ZERO of them (Racket 8.17 and 9.3); PLTSTDERR=debug@GC shows "0:atexit"
     with no final collection.  So there is no exit-time finalizer sweep for a
     corrupted free path to blow up in.
  2. In-place overwrite of the mapped libtorchrkt is INERT on darwin.  Zeroing
     the ENTIRE ~195 KB dylib under a live REPL and then calling six cold ops
     changed nothing -- the shim is fully resident after load, so file writes
     never reach the mapped pages.
  3. Every one of the 33 tensor-returning bindings carries a #:wrap, so every
     free goes through swallow-and-count-failure.  finalizer-failures was 0 in
     every single run.

Point 2 is the one most likely to differ on Linux: demand paging, a much larger
CUDA-linked shim, and glibc's loader behave differently from dyld.  And CUDA has
an entirely separate allocator and teardown path (caching allocator, context
teardown, driver unload at exit) that MPS does not exercise.  That is what this
run is for.  Full darwin measurements: docs/exit-loop-findings.md

WHAT "REPRODUCED" LOOKS LIKE
----------------------------
  - runaway repeated "invalid memory reference.  Some debugging context lost"
  - a growing nested message: "...; original exception raised: exception raised
    by error display handler: ...; original exception raised: ..."   (this
    nesting IS the unbounded RSS growth -- the message is re-concatenated every
    round, so printing it is O(n^2))
  - SIGTERM ignored, process eventually SIGKILLed
Any of those makes the harness print a FAIL line and keep the transcript.

--------------------------------------------------------------------------------
0.  SETUP (on the CUDA host)
--------------------------------------------------------------------------------
    git fetch origin
    git checkout debug/exit-loop
    git add -A                # the flake builds from the git-TRACKED tree;
                              # untracked files cause "Cannot find source file"

    # Stage a matching native lib.  The dev shell only re-stages on FIRST
    # provision (the deps_stamp guard), so do this explicitly:
    CPP_OUT=$(nix build .#cpp --print-out-paths | tail -1) \
      && rm -f torch/native-libs/libtorchrkt.* \
      && cp "$CPP_OUT"/lib/libtorchrkt.* torch/native-libs/ \
      && chmod u+w torch/native-libs/libtorchrkt.*
    find torch examples -type d -name compiled -exec rm -rf {} +
    nix develop --command raco setup --no-docs --pkgs torch

  A MISMATCHED lib vs bytecode is itself a fault source, so do not skip this.

1.  CPU ARM  (baseline -- should be clean; proves the harness works)
--------------------------------------------------------------------------------
    nix develop --command ./scripts/repro/run-all.sh cpu 20

--------------------------------------------------------------------------------
2.  CUDA ARM  (the real question)
--------------------------------------------------------------------------------
  The CUDA shell swaps in the CUDA-linked shim and puts the host driver on
  LD_LIBRARY_PATH.  Sanity-check the device first:

    nix develop .#cuda --command racket scripts/repro/preflight.rkt
        # expect: cuda-available: #t   and a nonzero device count

    nix develop .#cuda --command ./scripts/repro/run-all.sh cuda 20

  If preflight says cuda-available: #f, stop -- every shape will ABORT rather
  than silently degrade to CPU (that is deliberate).

--------------------------------------------------------------------------------
3.  THE #72 VECTOR  (overwrite the mapped lib under a live REPL)
--------------------------------------------------------------------------------
  This is the one measured INERT on darwin.  Run it on Linux, both modes, both
  devices.  It backs the library up and restores it afterwards.

    nix develop .#cuda --command bash -c 'REPRO_DEVICE=cuda ./scripts/repro/corrupt-restage.sh restage'
    nix develop .#cuda --command bash -c 'REPRO_DEVICE=cuda ./scripts/repro/corrupt-restage.sh zero'
    nix develop       --command bash -c 'REPRO_DEVICE=cpu  ./scripts/repro/corrupt-restage.sh zero'

  "restage" = re-copy identical bytes in place, exactly what
  `nix run .#copy-native-libs` does.  "zero" = worst case.
  If EITHER produces the cascade on Linux, #72's fix (atomic rename staging) is
  confirmed as the right fix and should land.

--------------------------------------------------------------------------------
4.  IF IT REPRODUCES -- capture this while it is still spinning
--------------------------------------------------------------------------------
  The loop runs for a while before dying, so ATTACH.  In another shell:

    pid=$(pgrep -n racket)
    gdb -p $pid -batch -ex 'thread apply all bt' > /tmp/rktorch-bt.txt   # or:
    eu-stack -p $pid > /tmp/rktorch-bt.txt
    grep -E 'VmRSS|Threads' /proc/$pid/status
    cat /proc/$pid/maps | grep -E 'libtorchrkt|libtorch_cuda' > /tmp/rktorch-maps.txt

  For symbolized native frames the nix build is stripped Release; build your own
  with symbols and point native-libs at it:

    cmake --preset dev && cmake --build --preset dev      # CMAKE_BUILD_TYPE=Debug
    cp cpp/build/libtorchrkt.so torch/native-libs/

--------------------------------------------------------------------------------
5.  ALWAYS-ON INSTRUMENT (works outside the harness too)
--------------------------------------------------------------------------------
  This branch makes the swallowed finalizer failures talk.  Previously
  swallow-and-count-failure kept a bare counter and DISCARDED the exception,
  which is why there was no evidence to work from.

    RKTORCH_MEM_TRACE=1 racket -i          # at exit, on stderr:
    [rktorch mem] ((runs . 4986) (failures . 0) (messages) (ledger-entries . 14))

  runs     = native frees the GC actually performed
  failures = frees that threw and were swallowed  <-- ANY nonzero value is the bug
  messages = up to 8 captured exception messages  <-- the actual evidence
  ledger   = handles still charged at exit

  Set RKTORCH_MEM_TRACE=1 in your normal CUDA REPL sessions for a while.  If the
  cascade happens again, that line is what identifies it.
  Also readable at the REPL: (finalizer-diagnostics)

--------------------------------------------------------------------------------
NOTES / GOTCHAS
--------------------------------------------------------------------------------
  * Everything must run from the repo ROOT.
  * `racket -i` auto-loads xrepl with no ~/.racketrc.  On a tty, Ctrl-D on a
    NON-EMPTY line is delete-char, not EOF -- that is why pty-ctrl-d.py sends a
    bare CR first.
  * s6-oom-churn deliberately allocates 2^60 floats (beyond ADDRESS SPACE).  Do
    not "fix" it to a merely huge number: on macOS a 4 TB request is accepted as
    a reservation and the process is SIGKILLed while zero-filling it, before the
    OOM classifier ever runs.  Linux overcommit may do the same.
  * The finalizer guard landed 3eac103 (2026-08-17).  Incidents before that date
    are the pre-guard #38 cascade and say nothing about master.
  * Adjust iteration count with the 2nd arg to run-all.sh.  20 separates "never"
    from "1-in-10"; use 50+ if you suspect a rarer race.
  * knobs: REPRO_DEVICE (cpu|cuda|mps)  REPRO_TIMEOUT (sec)  REPRO_LOGDIR
